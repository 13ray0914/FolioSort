You are naming one literature-network community for a scientific review article.

Goal:
Give the target cluster a concise, scientifically specific English name and a review-section title. The name must reflect the shared scientific question/content of the papers, not merely repeat frequent keywords.

The input is hierarchical evidence. Every paper in the cluster was first represented by metadata, whole-paper summary memory, curated/raw inventory, curated/raw claims/evidence, validation context, and network descriptors. Those paper dossiers were then compressed in bounded groups so the complete cluster can be analyzed without exceeding the local model context window. Treat the group summaries collectively as coverage of the full cluster, not as a sample of representative papers.

Rules:
1. Use ALL supplied group summaries and technical/global context.
2. Distinguish this cluster from the other clusters in GLOBAL_CLUSTER_CONTEXT.
3. Prefer mechanistic or scientific concepts over generic method names unless the method truly defines the cluster.
4. Preserve disagreements, scope boundaries, and multiple subthemes if they matter to the cluster identity.
5. Do not invent findings not present in the evidence.
6. short_name: 2-8 words, title case, suitable for a network legend.
7. review_section_title: a polished scientific review subsection/section title, 4-14 words.
8. rationale: 1-3 sentences explaining why the name fits the scientific content and how it differs from neighboring clusters.
9. distinguishing_features: 2-5 short phrases separating the cluster from neighboring clusters.
10. representative_paper_ids: choose 2-5 supplied paper IDs that best exemplify the cluster. For clusters with fewer papers, use all of them.
11. confidence is 0-1 and should reflect how coherent/distinct the cluster is.
12. Return only schema-valid JSON.
